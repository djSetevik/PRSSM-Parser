# PRSSM-Parser

Конвертер балочных пролётных строений в формат `.prssm` для PARIS. Два режима входных данных:

- **АРГО-ЖБ** — железнодорожные ПС, прежний парсер и алгоритм конвертации.
- **BearingCapacity** — автомобильные балки, XML-файлы `.bdf`, сечения `ais7GbBeamType1` и `ais7GbBeamType2`.

Откройте `PRSSM-Parser.slnx` или соберите проект:

```powershell
dotnet build PRSSM-Parser.slnx -c Release
```

Программа: `PRSSM-Parser/bin/Release/net8.0/PRSSM-Parser.exe`. Требуется .NET 8. Решение и основной проект называются `PRSSM-Parser`, тестовый проект — `PRSSM-Parser.Tests`, пространство имён — `PrssmParser`. Обработчики форматов находятся в каталогах `Argo` и `BearingCapacity`.

## Использование

При запуске без аргументов программа предлагает выбрать формат, входной файл или папку, папку результатов и один файл либо весь банк. Пустой ответ на выбор формата включает прежний режим АРГО.

Входные банки копируются рядом с программой при сборке и публикации:

| Режим | Вход по умолчанию | Выход по умолчанию |
| --- | --- | --- |
| АРГО-ЖБ | `Data/RAW` | `Data/PRSSM` |
| BearingCapacity | `Data/BDF` | `Data/PRSSM/BDF` |

В `Data/BDF` включены 289 предоставленных типовых моделей автомобильных балок. Можно указать внешнюю папку без копирования файлов.

```powershell
.\PRSSM-Parser.exe --format bdf --input "D:\Documents\PROJECTS_CODE\Типовики АД" --output "D:\Export\AD"
.\PRSSM-Parser.exe --format argo --input ".\Data\RAW" --output "D:\Export\Railway"
.\PRSSM-Parser.exe --help
```

Подпапки сохраняются. В режиме АРГО имя результата осталось прежним: `A4_0640.02p` → `A4_0640_02p.prssm`. В режиме BDF заменяется расширение: `model.bdf` → `model.prssm`. Повторная конвертация заменяет одноимённые результаты. Ошибка одного файла не прерывает обработку остальных. Код завершения: `0` — успех, `1` — ошибки отдельных файлов, `2` — ошибка аргументов или входного пути.

## Перенос BearingCapacity

Алгоритмы сверены с кодом `Ais7BearingCapacity.exe` и `Ais7PassConditionCore.dll`, а не с предположениями по названиям полей. Контуры и крутильные характеристики сверены с результатами вызова исходной DLL для всех 289 моделей.

- Один BDF описывает **одну типовую балку**, без схемы расстановки балок в пролёте. Поэтому экспортируется одна балка с полной длиной `L_full` и опорными осями, определяемыми `Lp`. `Loch` — длина площадки опирания, она не подменяет консоль балки.
- Переносятся основной контур `Profile`, верхний и нижний вуты, линейные сопряжения и скругления, консоли полки и класс бетона. Длины из метров переводятся в миллиметры; диаметры уже заданы в миллиметрах.
- Источники арматуры — `ReinLow` и `ReinTop`. Вычисленные списки `ReinTopList`, `ReinPresLowList`, `ReinPresTopList` повторно не добавляются. Поддержаны старые имена `RainLow`/`RainTop`.
- Переносятся поперечная симметрия `IsSymm`, прямые стержни, отгибы `ZType`, ломаные `CurveType`, пучки, диаметр проволоки, классы материалов и признак преднапряжения. Продольные координаты отсчитываются от середины балки и раскрываются на полную длину.
- Участки хомутов переносятся как открытые вертикальные ветви с исходными `Count`, `NCount`, `Step`, `Y`, `Z`, `H1`. Поперечная раскладка и замыкание в исходном BDF отсутствуют.

Рядом с результатами BDF создаётся **`conversion-report.json`**: параметры прочитанной модели, замечания и ошибки по каждому файлу. До расчёта в PARIS проверьте замечания конкретной модели:

- `HorizBarCount*`/`HorizBarD*` и `HBarCount`/`HBarD` задают вспомогательную арматуру без координат. Эти величины сохраняются в отчёте; геометрия стержней по ним не выдумывается.
- Опорные уширения `b2`/`a1`/`a2` влияют на расчёт поперечной силы в BearingCapacity, но не входят в его основной `Profile`. Они сохраняются в отчёте; переменные сечения по длине пока не формируются.
- В BDF нет исходных усилий натяжения и полного набора параметров потерь. `sigma_pc1` — напряжение верхней арматуры после потерь, оно сохраняется в отчёте и не подставляется вместо усилия натяжения.
- Значение класса арматуры `None` сохраняется без автоматической подмены; в пяти моделях предоставленного банка требуется назначить материал части верхних стержней. Переопределения `Rs_int` и аналогичные поля сохраняются в отчёте; в PRSSM используются стандартные классы материалов.

Формирование плит, связей, нагрузок и проездов в прежнем режиме АРГО не изменено. В режиме BDF эти объекты не создаются: файл описывает типовую балку.
